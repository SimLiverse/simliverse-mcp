# Isaac Sim 6.0.0 Support — Design

## Goal

Make `isaacsim-mcp-server` run cleanly against Isaac Sim 6.0.0 under **both** physics backends — PhysX (default launcher `isaac-sim.sh`) and Newton (opt-in launcher `isaac-sim.newton.sh`). Detect the runtime version and active engine automatically. Keep 5.1.0 working unchanged.

## Context: what changed in 6.0.0

Isaac Sim 6.0.0 reorganizes the Python namespace around three ideas:

1. **A new "Core Experimental" API** (`isaacsim.core.experimental.{utils,prims,objects,actuators,materials}`) built on `warp` and `omni.physics.tensors`. Long-term replacement for `isaacsim.core.{api,prims,utils}`.
2. **A new `SimulationManager` singleton** (`isaacsim.core.simulation_manager`) that owns physics backend selection (`physx` vs `newton` vs `remotesim`) and supersedes `World` / `SimulationContext`.
3. **Newton physics as a peer to PhysX**, shipped via a separate launcher. The default launcher uses PhysX (`isaacsim.core.simulation_manager/config/extension.toml:37` sets `default_engine = "physx"`). The Newton kit explicitly disables every PhysX-bundled extension.

### Why a thin V6 inheriting from V5 will not work under Newton

The Newton kit (`apps/isaacsim.exp.full.newton.kit`) sets:

```toml
"omni.physics.physx"     = { enabled = false }
"omni.physx.bundle"      = { enabled = false }
"omni.physx.fabric"      = { enabled = false }
"omni.physx.graph"       = { enabled = false }
"omni.physx.camera"      = { enabled = false }
"isaacsim.sensors.physx" = { enabled = false }
"omni.physics.stageupdate" = { enabled = false }

[settings.exts."omni.physx"]     enabled = false
[settings.exts."omni.usdphysics"] enabled = false
```

The legacy extensions the V5 adapter depends on transitively pull these in:

| V5 adapter import | Legacy ext that breaks under Newton | Why |
| --- | --- | --- |
| `isaacsim.core.api.World` / `SimulationContext` | `isaacsim.core.api` | declares `"omni.physics.physx" = {}` in `extsDeprecated/isaacsim.core.api/config/extension.toml` |
| `isaacsim.core.prims.SingleArticulation` / `SingleXFormPrim` | `isaacsim.core.prims` | declares `"omni.physx.tensors" = {}` (peer of `omni.physics.tensors`, ships in the disabled bundle) |
| `isaacsim.core.utils.{prims,stage,types}` | `isaacsim.core.utils` | declares `"omni.physics.physx" = {}`, `"omni.physx" = {}` |
| `isaacsim.sensors.camera.Camera` | `isaacsim.sensors.camera` | depends on `isaacsim.core.api` |
| `isaacsim.sensors.rtx.LidarRtx` | `isaacsim.sensors.rtx` | depends on `isaacsim.core.api` |
| `omni.physx.get_physx_interface().get_rigidbody_transformation()` | `omni.physx` | explicitly disabled at settings level |

So at adapter construction time under Newton, every one of those `from isaacsim.core.* import ...` lines raises `ImportError`. V5 inheritance is structurally broken under Newton, not just noisy.

### What does work under both kits

| Component | Status under PhysX | Status under Newton |
| --- | --- | --- |
| `isaacsim.core.simulation_manager.SimulationManager` | ✓ | ✓ — owns engine selection |
| `isaacsim.core.experimental.utils.stage` / `prim` / `xform` | ✓ | ✓ — no PhysX deps |
| `isaacsim.core.experimental.objects.{Cube,Sphere,Cylinder,Cone,Capsule,GroundPlane,Mesh,Camera}` | ✓ | ✓ — deps on `experimental.{materials,prims,utils}` |
| `isaacsim.core.experimental.prims.{XformPrim,RigidPrim,GeomPrim,Articulation}` | ✓ | ✓ — uses `omni.physics.tensors` (unified) |
| `isaacsim.core.experimental.materials` | ✓ | ✓ |
| `isaacsim.asset.importer.urdf.URDFImporter` / `URDFImporterConfig` | ✓ | ✓ — USD generator, not backend-coupled |
| `isaacsim.sensors.experimental.rtx.{RtxCamera,CameraSensor,Lidar,LidarSensor}` | ✓ | ✓ — RTX-based, no PhysX deps |
| `isaacsim.storage.native.get_assets_root_path` | ✓ | ✓ — unchanged from 5.1 |
| `omni.{usd,kit.commands,timeline,kit.app,client}` | ✓ | ✓ — kit framework |

That is the API surface V6 must be built on.

## Scope: a full V6 adapter on the experimental APIs

V6 is **not** a thin override of V5. It is a separate concrete implementation of `IsaacAdapterBase` that:

1. Builds on `isaacsim.core.experimental.*` + `SimulationManager` + `isaacsim.sensors.experimental.rtx` + `isaacsim.asset.importer.urdf.URDFImporter`. Backend-neutral by construction.
2. **Auto-detects the active engine** at construction time via `SimulationManager.get_active_physics_engine()`. The same code path runs under both `physx` and `newton`; engine information is stored on the adapter for diagnostics and for the small number of methods that need backend-specific behavior (currently none beyond logging).
3. Keeps the V5 adapter file unchanged so 5.1.0 users see no regression.

`get_adapter()` picks V5 vs V6 by Isaac Sim major version (no engine logic at the dispatcher level — the V6 adapter handles both engines internally):

```python
def get_adapter() -> IsaacAdapterBase:
    if _detect_isaacsim_major_version() >= 6:
        from .v6 import IsaacAdapterV6
        return IsaacAdapterV6()
    from .v5 import IsaacAdapterV5
    return IsaacAdapterV5()
```

Version detection: try `isaacsim.core.version.get_version()` first (present in both 5.1 and 6.0 under `exts/isaacsim.core.version/`), fall back to reading the install's `VERSION` file. On total failure, default to V5 — safe under 5.1, slightly worse under PhysX 6.0 (deprecation warnings), broken under Newton (clear `ImportError` traceback the user can act on).

## V6 implementation, method by method

The mapping below is the contract V6 must implement. Every entry is a method on `IsaacAdapterBase` that V5 currently implements one way and V6 must implement on experimental APIs. Behavior shape (return types, error contracts) stays the same so the existing handlers don't change.

### Scene / stage

| `IsaacAdapterBase` method | V6 implementation |
| --- | --- |
| `get_stage()` | `omni.usd.get_context().get_stage()` (unchanged) |
| `get_assets_root_path()` | `isaacsim.storage.native.get_assets_root_path()` (unchanged) |
| `discover_environments()` / `discover_robots()` | unchanged — uses `omni.client.list` |
| `load_environment()` / `add_reference_to_stage()` | `isaacsim.core.experimental.utils.stage.add_reference_to_stage(usd_path, prim_path)` |
| `create_prim(path, type)` | `isaacsim.core.experimental.utils.stage.define_prim(path, type_name=type)` |
| `delete_prim(path)` | `isaacsim.core.experimental.utils.stage.delete_prim(path)` (or kit `DeletePrims` command — both work) |
| `set_prim_transform` / `get_prim_transform` | direct `pxr.UsdGeom.Xformable` (unchanged) |
| `list_prims` | unchanged (USD traversal) |
| `get_prim_info` / `get_prim_actual_size` | unchanged (USD attributes) |

### Robots / articulations

The hard part. `isaacsim.core.experimental.prims.Articulation` is a multi-prim, batched, `wp.array`-based API. The handler layer assumes single-robot numpy-list outputs (e.g. `set_joint_positions(positions: Sequence[float])`). V6 wraps the batched API as if it's a single-prim adapter:

| Method | V6 implementation |
| --- | --- |
| `create_xform_prim(path)` | `isaacsim.core.experimental.prims.XformPrim(paths=[path])` |
| `create_articulation(path, name)` | `isaacsim.core.experimental.prims.Articulation(paths=[path])` |
| `get_robot_joint_info(path)` | build single `Articulation([path])`, read `dof_names`, `num_dofs`; for limits fall back to USD traversal as today |
| `set_joint_positions(path, positions)` | build `Articulation([path])`, call `set_dof_position_targets(wp.array([positions]))`. USD-drive fallback unchanged for stopped-sim case. |
| `get_joint_positions(path)` | `Articulation([path]).get_dof_positions().numpy()[0].tolist()` with USD-drive fallback |
| `get_joint_config(path)` | combines USD traversal (limits, drive type, stiffness/damping) with `Articulation` runtime reads (current positions, applied targets) |

We do not cache `Articulation` instances across calls; they are cheap to construct, and reusing them across stop/play cycles is the documented pitfall called out in the MCP server instructions. Each adapter call constructs, queries, and discards.

### Physics

| Method | V6 implementation |
| --- | --- |
| `create_world` | `SimulationManager` is a singleton; method returns the class itself (or a thin proxy that exposes `step` / `reset`). Most callers use it for `_ensure_physics_world` semantics. |
| `create_simulation_context` | same — returns `SimulationManager` |
| `_ensure_physics_world` | `SimulationManager.setup_simulation(dt=1.0/60.0)` + `SimulationManager.initialize_physics()`. Both are idempotent. No `World.instance()` fallback — that's a 5.1 thing. |
| `create_physics_scene(gravity, scene_name)` | unchanged — `omni.kit.commands.execute("CreatePrim", prim_type="PhysicsScene")` works under both backends |
| `get_physics_state(path)` | USD attributes for static info (RigidBodyAPI, MassAPI, CollisionAPI), and `SimulationManager.get_physics_simulation_view()` → `RigidBodyView` for live linear/angular velocity. Backend-neutral. No `omni.physx` import. |

### Simulation control

| Method | V6 implementation |
| --- | --- |
| `play` / `pause` / `stop` | `isaacsim.core.experimental.utils.app.{play,pause,stop}` — wraps `omni.timeline` but with the `_ensure_physics_world` call woven in |
| `step(num_steps, observe_prims, observe_joints)` | `isaacsim.core.experimental.utils.app.update_app(steps=num_steps)`. For `observe_prims` rigid-body reads, use the same `SimulationManager.get_physics_simulation_view()` path as `get_physics_state`. For `observe_joints`, use the `Articulation` wrapper from above. |
| `get_simulation_state` | `omni.timeline` for state name + current time. `SimulationManager.get_simulation_time()` and `SimulationManager.get_num_physics_steps()` for richer info. |
| `execute_script(code, cwd)` | unchanged — `exec()` against an injected namespace, with `_ensure_physics_world` called first |
| `reload_script(file_path, module_name)` | unchanged — `importlib.reload` plus `exec()` flow, just using V6's `_ensure_physics_world` |

### Sensors (cameras, lidar)

V6 uses `isaacsim.sensors.experimental.rtx` for both backends. The experimental API splits sensor *authoring* (creating the USD prim with the right schema) from sensor *runtime* (a handle that reads frames). V6 hides that split behind the adapter's `create_camera` / `capture_camera_image` interface:

| Method | V6 implementation |
| --- | --- |
| `create_camera(path, resolution, **kwargs)` | `RtxCamera(prim_paths=[path], resolutions=[resolution])` for authoring. Cache the prim path on the adapter, not the runtime handle. |
| `capture_camera_image(path)` | construct `CameraSensor` against the prim path, attach rgb annotator, render-tick, return the RGB ndarray. |
| `create_lidar(path, config, **kwargs)` | `Lidar(prim_paths=[path], configs=[config or "Example_Rotary"])` — `SUPPORTED_LIDAR_CONFIGS` lists valid names. |
| `get_lidar_point_cloud(path)` | construct `LidarSensor` against the prim path, render-tick, return point-cloud ndarray. |

We do not preserve the legacy `isaacsim.sensors.camera.Camera` / `isaacsim.sensors.rtx.LidarRtx` API in V6. The experimental sensor API is fundamentally different (authoring vs runtime, annotator-based reads) and routing the legacy one through V6 only buys deprecation warnings under PhysX while still breaking under Newton.

### Materials and lighting

`isaacsim.core.experimental.materials` covers PBR + physics materials. V6:

| Method | V6 implementation |
| --- | --- |
| `create_pbr_material` | direct `pxr.UsdShade.Material.Define` + `UsdShade.Shader.Define` with `UsdPreviewSurface` (no Isaac dependency — works everywhere) |
| `create_physics_material` | direct `pxr.UsdPhysics.MaterialAPI.Apply` (USD schema, no Isaac dependency) |
| `apply_material` | `pxr.UsdShade.MaterialBindingAPI` (no Isaac dependency) |
| `create_light` / `modify_light` | direct `pxr.UsdLux` (no Isaac dependency) |
| `clone_prim` | `omni.kit.commands.execute("CopyPrim", ...)` (kit framework) |

These are all USD-schema operations and don't change between 5.1 and 6.0. V6 keeps the V5 implementation verbatim.

### Assets

| Method | V6 implementation |
| --- | --- |
| `import_urdf(urdf_path, prim_path, **kwargs)` | `URDFImporter(URDFImporterConfig(urdf_path=urdf_path, dest_path=prim_path, **kwargs)).import_urdf()`. Returns `{"prim_path": result_path}` (same shape as V5). |

The legacy kit commands (`URDFCreateImportConfig` etc.) still resolve under PhysX but print a deprecation warning per call. Under Newton, `isaacsim.asset.importer.urdf.ui` may or may not register them (the UI extension may still load) — either way, V6 doesn't use them.

## Engine detection and reporting

`IsaacAdapterV6.__init__`:

```python
self._engine = SimulationManager.get_active_physics_engine()  # "physx" | "newton" | "remotesim"
self._isaacsim_version = isaacsim.core.version.get_version()
```

The adapter exposes this through a new diagnostic field on `get_simulation_state`:

```json
{
  "timeline_state": "playing",
  "current_time": 1.23,
  "physics_dt": 0.0166,
  "engine": "newton",
  "isaacsim_version": "6.0.0-rc.59+release.41464.5f2772bc.gl"
}
```

Handlers don't have to change — they pass the dict through. Tools that surface state get this info for free, which makes "which backend is the user on?" debuggable from the MCP client side without inspection commands.

## Risks and how we address them

1. **Experimental APIs are `-rc.59`.** Surface may shift before 6.0 GA. *Mitigation:* hide each call behind a single adapter method. If a method signature changes, only V6 needs editing. Implementation plan should pin to `isaacsim.core.experimental.*` versions seen in the local install (1.8.8, 0.8.0, 0.17.1 today).
2. **`isaacsim.core.experimental.prims.Articulation` is batched.** Translating to single-prim numpy adds overhead per call (constructing `wp.array` for a single prim, reading back via `.numpy()[0]`). *Mitigation:* acceptable for editor-level diagnostics, which is the entire MCP server. If it shows up in profiles, cache the `Articulation` instance per prim path with invalidation on timeline stop.
3. **Newton API gaps.** Some PhysX-only features (contact reports via `omni.physx`, PhysX-specific sensor implementations) have no Newton equivalent yet. *Mitigation:* the V6 sensor + state methods use only the unified `omni.physics.tensors` view and RTX sensors — none of those have a PhysX-only counterpart in the current adapter surface.
4. **Newton kit blocks PhysX-bundled tools we don't currently call but might add later.** *Mitigation:* any new adapter method that needs PhysX must check `self._engine` and either degrade or return a structured error.
5. **Side-by-side installs (5.1 + 6.0 on the same machine, like the user's box).** *Mitigation:* version detection reads the runtime that actually loaded the extension via `isaacsim.core.version.get_version()`; the local filesystem layout doesn't matter.

## Testing

Three layers:

1. **Pure-Python unit tests** (`tests/test_adapter_v6.py`): mock `isaacsim.*` imports and assert V6 calls the right experimental APIs with the right arguments. Doesn't need Isaac Sim installed; can run in CI.
2. **PhysX smoke test** (`scripts/smoke_test_v6_physx.py`): runnable inside `isaac-sim.sh` (the default 6.0 launcher). Creates Franka, sets joint positions, steps, reads `get_physics_state`. Replicates the existing 5.1 demo flow.
3. **Newton smoke test** (`scripts/smoke_test_v6_newton.py`): runnable inside `isaac-sim.newton.sh`. Same flow but expected to validate the Newton path end-to-end.

Smoke tests are documented in `CONTRIBUTING.md` and gated behind `ISAACSIM_VERSION=6.0` + `ISAACSIM_ENGINE={physx,newton}` env vars. Not in CI today; we rely on developer run before tagging the release.

## Out of scope (followups)

- Removing V5. Once 5.1 share drops, V5 can be deleted; not now.
- Newton-specific MCP tools (e.g. `switch_physics_engine`, contact-graph reads via Newton). Possible later.
- Migrating articulation handlers from single-prim to multi-prim batched semantics. The MCP tool surface is single-prim today and that doesn't need to change.
- `isaacsim.core.experimental.actuators` — actuator authoring; not exposed by current MCP tools.

## Acceptance criteria

- `get_adapter()` returns `IsaacAdapterV6` when run inside Isaac Sim 6.0.0 under either launcher; `IsaacAdapterV5` when run inside 5.1.0.
- Under `isaac-sim.sh` (PhysX, 6.0.0): full MCP tool surface works, no `URDFCreateImportConfig is deprecated` / `World deprecated` warnings, demo `franka_pick_place.py` runs to completion.
- Under `isaac-sim.newton.sh` (Newton, 6.0.0): scene creation, robot import, joint set/read, step, get_physics_state, camera capture, and lidar point cloud all work without `ImportError`.
- `get_simulation_state` returns `engine` and `isaacsim_version` fields and they are correct in both launchers.
- `tests/test_adapter_v6.py` passes with no Isaac Sim installed (mocked imports).
- V5 adapter file unchanged; 5.1 behavior unchanged.
- `pyproject.toml`, `extension.toml`, README updated to advertise Isaac Sim 5.1.0 and 6.0.0 (both PhysX and Newton) support.
